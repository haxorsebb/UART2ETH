== ADR-008: Hardware Pin Configuration

**Status:** Accepted

**Date:** 2025-08-27

**Context:** This document defines the current hardware pin configuration for the UART2ETH device, including all UART channels, Ethernet controller, and system interfaces.

=== Current Pin Configuration

The RP2350 pin assignment is optimized for PCB layout efficiency and signal integrity. The configuration supports up to 4 UART channels exposed as TCP sockets, with dedicated pins for Ethernet communication and system debugging.

==== Complete Pin Mapping

[cols="2,2,2,4"]
|===
|Function |GPIO |Interface |Description

|**Debug Interface**
|TX |GP0 |UART0 |Printf debug output via USB-CDC (/dev/ttyACM0)
|RX |GP1 |UART0 |Debug input (115200 baud)

|**Ethernet Controller (ENC28J60)**
|INTERRUPT |GP2 |Digital Input |Interrupt signal (active low)
|RESET |GP3 |Digital Output |Hardware reset control
|SCK |GP10 |SPI1 |SPI clock signal
|MOSI |GP11 |SPI1 |Master Out Slave In
|MISO |GP12 |SPI1 |Master In Slave Out

|**UART Channels**
|Channel 2 TX |GP4 |PIO |UART Channel 2 transmit (disabled)
|Channel 2 RX |GP5 |PIO |UART Channel 2 receive (disabled)
|Channel 3 TX |GP6 |PIO |UART Channel 3 transmit (disabled)
|Channel 3 RX |GP7 |PIO |UART Channel 3 receive (disabled)
|Channel 1 TX |GP8 |UART1 |UART Channel 1 transmit (active, 500000 baud)
|Channel 1 RX |GP9 |UART1 |UART Channel 1 receive (active, 500000 baud)
|===

==== Interface Details

===== Debug Interface (UART0)
- **Purpose**: System debug output and printf logging
- **Configuration**: 115200 baud, 8N1, no flow control
- **Access**: Available via USB-CDC interface as /dev/ttyACM0
- **Usage**: Core system logging, boot messages, diagnostic output

===== Active UART Channel (Channel 1)  
- **Purpose**: Primary TCP-to-UART bridge functionality
- **Configuration**: 500000 baud, 8N1, no flow control
- **TCP Port**: Exposed as TCP socket for network access
- **Protocol**: Custom message framing with '!\r\n' terminators

===== Ethernet Controller (ENC28J60)
- **Interface**: SPI1 at high speed for Ethernet packet processing
- **Reset Control**: Software-controlled hardware reset via GP3
- **Interrupt**: Packet reception and link status notifications via GP2
- **Buffer**: 8KB total (4KB RX, 4KB TX)

===== Future Expansion (Channels 2-3)
- **Implementation**: PIO-based UART for additional channels
- **Status**: Hardware pins reserved, software implementation pending
- **Potential**: Up to 4 total UART channels as originally specified

=== Hardware Design Benefits

==== SPI Interface Optimization
* **Pin Grouping**: SPI1 pins (GP10-GP13) are physically adjacent for optimal PCB routing
* **Signal Integrity**: Minimized trace lengths reduce EMI and crosstalk
* **High Speed**: SPI1 interface supports high-speed Ethernet packet processing

==== UART Interface Distribution  
* **Separation of Concerns**: Debug UART (UART0) separate from application UARTs
* **Hardware UART Usage**: Channel 1 uses UART1 hardware for reliable high-speed operation
* **PIO Expansion**: Channels 2-3 reserved for PIO implementation enabling additional UART channels

==== Debug and Development
* **Standard Debug Interface**: UART0 on GP0/GP1 follows RP2350 conventions
* **USB-CDC Integration**: Seamless debug access via USB connection
* **Manufacturing Support**: Easy access to debug pins during production testing

=== Implementation Notes

==== Driver Configuration
* **ENC28J60 Driver**: Pin definitions in `enc28j60_driver.h` lines 31-36
* **UART Manager**: Channel configurations in `uart_manager.c` lines 46-55
* **Debug Output**: Configured in CMakeLists.txt for UART0 hardware selection

==== Development Environment
* **Flashing**: Uses OpenOCD with CMSIS-DAP interface
* **Debugging**: GDB multiarch with OpenOCD server on port 3333
* **Serial Logging**: Persistent UART logger monitors /dev/ttyACM0

==== Testing Considerations
* **Hardware Verification**: All interfaces tested during firmware flashing process
* **Signal Quality**: SPI1 configuration verified for reliable Ethernet communication  
* **UART Channel Testing**: Channel 1 verified at 500000 baud operation
* **Debug Interface**: UART0 confirmed functional for system diagnostics

=== Pin Assignment Rationale

The current pin assignment prioritizes:

1. **Manufacturing Efficiency**: Grouped interfaces minimize PCB complexity
2. **Signal Quality**: High-speed interfaces use optimal pin locations
3. **Development Support**: Standard debug interfaces for easy development
4. **Future Expansion**: Reserved pins for additional UART channels
5. **System Reliability**: Hardware reset and interrupt capabilities

=== Compatibility Notes

* **Hardware Dependency**: Pin configuration is hardware-specific and cannot be changed via software
* **Firmware Binding**: Compiled firmware is tied to this specific pin configuration
* **Development Tools**: Debug tools must connect to UART0 (GP0/GP1) for system access
* **Network Integration**: Ethernet functionality depends on correct SPI1 and control pin configuration
